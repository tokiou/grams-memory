GRAMS / Supervisor v2

El camino de nodos, explicado sin magia.

El Supervisor consume eventos durables, carga el proceso actual, usa Jev para decisiones acotadas, OpenRouter para redactar, y Python + Memory MCP para validar, guardar y enrutar.

Regla principalJev decide. OpenRouter redacta. Python controla. Memory MCP conserva la memoria durable. Inbox conserva los eventos y sus leases.

3. Qué hace cada nodo

Abre cada tarjeta. El nombre de la derecha es el script que implementa el nodo.

Inbox
READ_INBOXnodes/read_inbox.py

Obtiene una cohorte completa de eventos para un root_session_id. El Inbox asigna lease_id y cycle_id, para que el retry conserve identidad.

  • Busca: eventos PENDING o leases expirados en SQLite.
  • Guarda: nada nuevo; devuelve eventos serializables al estado LangGraph.
  • Protege: no mezcla cohorts y no reclama un root con otra cohorte activa.
Python
ENSURE_ACTIVE_PROCESSnodes/ensure_active_process.py

Resuelve el Project de la sesión y garantiza un proceso activo. También detecta cierres/transiciones incompletos.

  • MCP: ensure_session_project, get_active_process, list_processes, get_process, create_process.
  • Guarda: Project/proceso mediante MCP si faltan.
  • Salida: project_id, active_process_id, flags de recuperación.
MCP
LOAD_PROCESS_CONTEXTnodes/load_process_context.py

Carga una vista compacta y aislada del proceso activo antes de cualquier decisión.

  • MCP: get_process, get_manifest, search por Project/Key/Category, neighbors, list_processes.
  • Busca: categorías STRATEGY, EVIDENCE, SUMMARY, relaciones y procesos predecessor/successor.
  • Guarda: solo en estado transitorio: process_context; la fuente durable sigue siendo MCP.
  • Control: máximo 50 por categoría y metadata de paginación.
Jev
ASSESS_PROCESS_CONTINUITYnodes/assess_process_continuity.py

Pregunta si la ejecución continúa la misma estrategia o representa un pivot material.

  • Pregunta: choice con SAME_PROCESS y NEW_PROCESS.
  • Guarda: decisión, distribución completa y confidence en process_continuity.
  • Regla Python: JEV_NEW_PROCESS_MIN_PROB determina el corte.
  • No hace: no inventa nombres ni escribe MCP.
OpenRouter
EXTRACT_MEMORY_CANDIDATESnodes/extract_memory_candidates.py

Extracts factual, evidence-backed candidates from recent execution. It does not decide what to retain or create relations.

  • Generates: bounded facts with event excerpts and provenance.
  • References: sequential local candidate IDs such as new_1.
  • Persists: candidates only in transient graph state.
Jev
CURATE_MEMORY_CANDIDATESnodes/curate_memory_candidates.py

Decides which candidates should persist and assigns memory metadata and supported relations.

  • Decides: keep/drop, category, role, status, progress effect, and importance.
  • Relates: kept candidates to each other or existing process memories.
  • Persists: curation decisions only in transient graph state.
OpenRouter
MATERIALIZE_MEMORIESnodes/materialize_memories.py

Turns kept factual candidates into concise memory titles and content.

  • Generates: one title/content pair per kept candidate.
  • Validates: the materialized output and assembles the update proposal.
  • Persists: the proposal in transient graph state; the following deterministic node writes MCP.
MCP
APPLY_MEMORY_UPDATEnodes/apply_memory_update.py

Convierte la propuesta de OpenRouter en escrituras deterministas y reconciliables.

  • Busca: memorias actuales del proceso y relaciones existentes.
  • Guarda: memory_create con category ID y source supervisor; memory_link para relaciones.
  • Idempotencia: deduplica por categoría/título/contenido y etiqueta con cycle_id:candidate_ref.
  • Valida: scope, categorías, refs locales, self-relations y relaciones duplicadas.
Jev
SUPERVISION_DECISIONnodes/supervision_decision.py

Es el centro de decisión. Hace dos llamadas Jev independientes.

  • Call 1: tres noul: progress stall, strategy supported, context sufficient.
  • Call 2: choice: CONTINUE, NEED_MORE_MEMORY, INTERVENE, CLOSE_PROCESS; además clasifica outcome terminal.
  • Guarda: diagnósticos, probabilidades, confidence, acción y targets MCP.
  • Reglas Python: context insuficiente fuerza expansión; baja confidence fuerza CONTINUE; outcome bajo fuerza no cerrar.
MCP
EXPAND_GRAPHnodes/expand_graph.py

Amplía contexto únicamente cuando Jev pide más memoria.

  • MCP: get, neighbors, search(offset), list_processes y load_process_context para procesos relacionados.
  • Busca: IDs dentro del proceso, relaciones permitidas, summaries y páginas antiguas.
  • Guarda: expanded_memory_context transitorio; nunca reemplaza el contexto normal.
  • Control: memory_expansion_depth y max_expansion_depth evitan loops.
OpenRouter
WRITE_PROCESS_SUMMARYnodes/write_process_summary.py

Comprime el proceso al cerrarlo.

  • Genera: resumen compacto de estrategia, evidencia, outcome y lecciones reutilizables.
  • Guarda: solo pending_process_summary validado en estado.
  • Después: el nodo MCP siguiente persiste el SUMMARY y cierra el proceso.
MCP
CLOSE_CURRENT_PROCESSnodes/close_current_process.py

Persiste el summary y cambia el proceso de ACTIVE a outcome terminal.

  • Busca: summaries por cycle_id para evitar duplicados.
  • Guarda: memory_create en categoría SUMMARY y close_process con SUCCEEDED/FAILED/ABANDONED.
  • Recuperación: si el summary ya existe, lo reutiliza; ProcessService puede reanudar cierre incompleto.
Python + MCP
START_NEW_PROCESSnodes/start_new_process.py

Crea el sucesor después de un pivot decidido por continuidad.

  • Busca: máximo nombre existente y sucesor ya creado.
  • Guarda: create_process con nombre determinista, por ejemplo process_002, y predecessor_id.
  • Limpia: transición pendiente, summary y expansión; fuerza reload del nuevo proceso.
OpenRouter
BUILD_INTERVENTIONnodes/build_intervention.py

Redacta un mensaje después de que Jev ya eligió INTERVENE.

  • Genera: texto breve, accionable y basado en evidencia.
  • Guarda: texto en intervention_message; no modifica MCP.
  • Restricción: no decide si intervenir ni resuelve la tarea.
Python + OpenCode
SEND_INTERVENTIONnodes/send_intervention.py

Entrega el mensaje al Action Agent con una intención durable.

  • Busca: evidencia auditora por cycle_id.
  • Guarda: estados PREPARED, SENDING, DELIVERY_UNKNOWN o DELIVERED en una memoria de evidencia.
  • Entrega: OpenCodeClient.send_message a la sesión raíz.
  • Seguridad: el texto persistido es canónico; una regeneración no lo reemplaza.
MCP
RECORD_INTERVENTIONnodes/record_intervention.py

Compatibilidad/auditoría final de la intervención.

  • Guarda: evidencia en categoría EVIDENCE si SEND aún no dejó auditoría.
  • Idempotencia: si existe audit_memory_id, no crea otra memoria.
Inbox
FINALIZEnodes/finalize_cycle.py

Cierra el ciclo durable, no el proceso semántico.

  • Guarda: ACK atómico de todos los pares (event_id, lease_id).
  • Si falla: el runtime ejecuta fail_batch y reencola la cohorte completa.
  • Limpia: estado transitorio de LangGraph para la siguiente ejecución.

4. Qué se guarda y dónde

Inbox SQLite

Fuente durable de ejecución.

  • payload/evento original
  • status PENDING/PROCESSING/PROCESSED/FAILED
  • lease, retry_count, cycle_id
  • objetivo original por sesión
  • ACK/fail de cohortes

Memory MCP

Fuente durable semántica.

  • Project y Process lifecycle
  • STRATEGY
  • EVIDENCE
  • SUMMARY
  • relations y predecessor
  • auditoría de intervenciones

LangGraph state

Solo coordinación temporal.

  • claimed events
  • context actual
  • propuestas y decisiones
  • expanded context
  • mensajes pendientes
  • resultados para el siguiente nodo
